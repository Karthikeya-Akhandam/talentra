# Integration Boundaries Specification
**Project:** Talentra — Job Search & Demand Management Platform  
**Organization:** Northbridge Workforce Systems  
**Document Ref:** Section 6 (Integration Boundaries)  

Talentra interfaces with 9 external systems. The platform stores operational state and reference keys, but does not duplicate external core state. The table below specifies data ownership, storage boundaries, failure modes, idempotency mechanisms, and audit logging for each integration boundary.

---

## Comprehensive Integration Boundaries Table

| Boundary | Data Ownership | Stored vs. Referenced Data | Failure Behavior & Resilience | Idempotency Mechanism | Audit Trail Implementation |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **1. Payment Gateway** (Stripe / Razorpay) | External Payment Gateway owns card processing, bank settlement, and PCI vault. | **Stored:** Internal order UUID, external gateway transaction reference, currency, payment amount, status (`pending`, `succeeded`, `failed`, `refunded`), timestamp.<br>**Referenced:** Gateway webhook tokens.<br>**Prohibited:** Cleartext card numbers, CVVs, or bank account credentials. | Circuit breaker with retry queue. Webhook events queued in `payment_webhook_log`. If gateway is unavailable, user UI presents a retryable pending state; scheduled reconciliation job verifies unconfirmed orders. | `gateway_transaction_id` unique constraint (`uq_payment_order_gateway_ref`). Gateway webhook events deduplicated by `idempotency_key` header. | Every inbound webhook payload hash, timestamp, previous status, and new status logged to `audit_log` and `payment_webhook_log`. |
| **2. Identity Verification Service** (National ID / KYC) | External Identity Provider (Govt/DigiLocker/Onfido) is source of truth for identity authenticity. | **Stored:** Verification outcome (`verified`, `failed`, `pending`), verification token, check timestamp, document type code.<br>**Prohibited:** Raw unmasked identity numbers in cleartext (stored only as SHA-256 salted hashes for deduplication). | Async verification queue. Candidate profile marks identity as `unverified` with limited platform privileges until webhook confirmation arrives. | Unique constraint on `(candidate_id, document_type_code, verification_provider_code)` with deterministic provider lookup token. | Every verification request submission, callback received, actor performing check, and status transition logged in `audit_log`. |
| **3. Company Registration & Tax Verification** (MCA / GSTIN / IRS) | Government / Official Tax Registrar. | **Stored:** Registration number, tax identifier (GSTIN, EIN), registered legal name, verification timestamp, verification status (`verified`, `flagged`, `rejected`). | Employer organization is created in `provisional` state. Job requisitions created under provisional status are held in `draft` and blocked from public candidate search until tax verification succeeds. | Unique constraint on `(country_code, tax_identifier_type, tax_identifier_value)` in `organisation_tax_identifier`. | Tax verification attempts, API response codes, and compliance officer overrides logged to `audit_log`. |
| **4. Gig Fulfilment System** | External Project / Gig Management Tool. | **Stored:** Handoff UUID, external contract reference, assignment status (`assigned`, `in_progress`, `completed`, `disputed`), start/end windows, reconciled final earnings figures.<br>**Referenced:** Work delivery milestones. Talentra does not run the work execution engine itself. | Circuit breaker pattern. Talentra maintains last known status; gig workers can access locally cached assignment details. Background reconciler synchronizes milestone completions every 15 minutes. | Unique constraint on `external_contract_reference` in `gig_external_handoff`. Updates require optimistic concurrency token (`version_id`). | All handoff creations, status shifts, and reconciled earnings postings logged in `audit_log` with source timestamp. |
| **5. Legacy Job & Candidate Systems** | Bi-directional with strict field-level governance. | **Stored:** Full candidate and job requisition data mapped to Talentra schema.<br>**Referenced:** `legacy_system_id`, `legacy_entity_type`, `legacy_sync_timestamp`.<br>**Sync Direction:** Candidates (Legacy $\to$ Talentra initially; Talentra $\to$ Legacy post-cutover). Jobs (Talentra $\to$ Legacy).<br>**Conflict Rule:** Latest update timestamp wins (`updated_at` comparison). | Dead-letter queue (`sync_dead_letter_queue`) for corrupt or conflicting records. Platform continues operational read/write; failed records flagged for manual reconciliation. | Deterministic mapping table `legacy_entity_mapping` with unique composite key `(legacy_source_system, legacy_entity_id)`. | Full diff payload before and after sync recorded in `audit_log`. |
| **6. Messaging & Notification Providers** (Email, SMS, WhatsApp) | External delivery provider owns delivery networks; Talentra owns templates and notification triggers. | **Stored:** Delivery status (`queued`, `sent`, `delivered`, `bounced`, `failed`), external provider message ID, delivery timestamp, recipient address/number, failure reason.<br>**Retention Rule:** Message bodies retained for 30 days for compliance, then purged; metadata retained permanently. | Multi-provider failover (e.g. Primary SMS $\to$ Secondary SMS provider). Failed dispatches retried up to 3 times with exponential backoff before being flagged `failed`. | Unique composite key `(notification_id, recipient_id, channel_type)` in `notification_delivery`. | Dispatches, provider webhooks, and bounce events recorded in `notification_delivery` and sensitive delivery failures recorded in `audit_log`. |
| **7. Social Sharing** | Talentra owns outbound sharing links; Social networks (LinkedIn, X) own external posts. | **Stored:** Outbound share event timestamp, actor ID, entity shared (`job_requirement_id`), destination channel code, generated tracking token (UTM code), click count.<br>**Prohibited:** External post content, user feed data, or personal social connections. | Fire-and-forget logging. If social share API or analytics tracker fails, fallback to simple clipboard URL copy with embedded tracking token. | Generated share token UUID unique in `social_share_event`. | Share events logged to `candidate_activity_log` for engagement analytics. |
| **8. Mapping & Geolocation Service** (Google Maps / Mapbox / OpenStreetMap) | External Geocoding Provider. | **Stored:** Latitude and longitude (`DECIMAL(10, 7)`), postal code, normalized city, geohash string.<br>**Referenced:** External Place ID.<br>**Resilience:** Treated as optional. | Cached geocodes stored locally in `geolocation_cache`. If external API is unreachable, fallback to administrative city/state centroid or manual postal code entry. | SHA-256 hash of normalized address string as primary key in `geolocation_cache`. | Geocoding lookups, cache hits, and provider response times tracked in `system_error_log`. |
| **9. Company Review & Salary Aggregators** | External Market Intelligence Aggregator. | **Stored:** Aggregate salary bands (p10, p25, p50, p75, p90), role title, experience level, location, company review rating score, total review count, refresh timestamp.<br>**Referenced:** Source aggregator code (`glassdoor`, `ambitionbox`, `payscale`). | Stale cache tolerance: Data is marked `is_stale = true` if refresh fails, but remains readable for benchmark comparisons. UI displays "As of [date]". | Composite unique key on `(company_id, job_role_id, location_id, data_source, snapshot_month)` in `salary_benchmark`. | Ingestion batch runs, imported row counts, and data discrepancy warnings logged in `audit_log`. |
